# V1.7.0 Release Notes
### Feature
- In multi-tenant mode, a tenant can be selected when creating an application. Member selection uses the new organization selector, and the built-in environment variable `BKPAAS_APP_TENANT_ID` is provided. ESB API applications are not available in this mode.
- Code repositories can be created in the Developer Center with a specified group. Dev sandboxes support custom environment variables, add-on services, Go, and passwordless login.
- Environment variables support the password type and masked display. Volumes support subpaths, Secrets, and custom capacity.
- Platform management can configure resource quotas for cloud-native applications. The app description file can reference these plans, and memory quotas add 16G and 32G. Cloud-native applications can set node selectors and tolerations per cluster.
- One S-mart package can create multiple applications and be built from different base images, with a packaging tool and a visible build process.
- The platform supports subpath access. Custom access addresses support multi-level paths and HTTPS.
- Cloud API permissions use the new gateway. They can be set to never expire and renewed directly after expiry. MCP Server permissions can be applied for, and application records can open the approval link.
- After an add-on service is unbound, reclamation can be deferred and done manually in the application or in platform management. Plans can be cloned. Platform management can permanently delete an application. Local resource pools support exact or fuzzy matching.
- The Redis add-on supports sentinel mode. The MySQL add-on generates passwords with stricter rules.
- Application category is part of basic information and is required before deployment. New applications include an example directory. A built-in AI plugin template is provided, and AI plugin applications can switch to source deployment.
- Cloud-native applications deployed from a code repository can view and edit processes on the process configuration page, and set a wait time before stopping.
- The homepage shows favorited applications and their deployment status.
- Creating an application with a reserved ID prefix requires an authorization code. Verification codes can be sent by SMS.

### Improved
- The application overview adds visit statistics and refreshes the charts. After a market address is set, the production address in the application list shows that address.
- Custom access addresses cannot use platform-reserved domains. A local add-on service cannot use the same name as an existing remote add-on service.
- Log retention and storage can be configured per environment, or use a shared collection item from the log platform. ES clusters can be configured per tenant. Subpath access does not provide access logs.
- Document links follow the interface language. Multiple built-in environment variables and different prefixes can be configured, and each variable indicates whether the application may override it.
- Platform management can maintain application templates. Cluster details show nodes, and hidden configuration can be expanded or collapsed at once.
- Code repository passwords are encrypted in transit on submit. Dependencies and base images are upgraded to improve platform security.

### Fixed
- Creating an application again after it is permanently deleted no longer keeps the old permission data.
- The bkrepo add-on can be allocated to applications under other tenants.
- With subpath deployment, the admin console works. Application members can be added, and custom access addresses open.
- After environment variables are published, the duration in deployment history is correct. S-mart applications can open the console.
- When TLS is off, the MySQL add-on and reserved instances can be allocated. When there is no restart record, viewing restart logs shows an explanation.
- Operation audit data can be migrated when upgrading from 1.5 to 1.7. Uploading a source package by link accepts only allowed addresses.
- Process resources of ordinary applications are shown as read-only. Changes still go through the original page.
