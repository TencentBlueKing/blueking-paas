# V1.8.0 Release Notes
### Feature
- Agent sandboxes are available, including isolated sandboxes and E2B sandboxes. Applications in the same tenant can share storage and manage files in the sandbox. Expired sandboxes are cleaned up, each application has a count limit, and deleting storage also removes the corresponding directory.
- Platform management can register sandbox templates and view or run operations commands. AI Agent applications can be created, and the build method can be chosen when uploading a source package.
- AppSpark can create a project, generate a project from a description, chat, choose a model per turn, preview, and publish to the Developer Center. Projects can be renamed, and deletion cleans up related resources.
- The permission center can switch to V4. It can sync the permission model, manage user groups and members, manage spaces, and migrate existing permissions.
- Sensitive configuration for the platform and applications can be loaded from the key management service. This is off by default. Applications can turn on encryption for sensitive environment variables.
- Image builds can pull base images through an image proxy. Application builds can turn on debug mode.
- Cloud API permission applications can be cancelled or deleted, and the approval link can be copied from the record. Request logs and alarm records can be viewed per application.
- Modules bound to the Redis add-on receive alarm policies. Redis adds configuration items, an environment variable template, and sentinel guidance, and supports per-instance quotas and metrics.
- The RabbitMQ add-on supports streams. A plan can select a cluster by cluster labels.
- The community edition registers MCP Servers for permission management and module deployment during initialization. The plugin center can turn permission sync on or off.
- The built-in environment variable `BKPAAS_NODEMGR_URL` is added. Cloud API gateway and MCP Server gain system APIs for applications to call.

### Improved
- Listing branches of a bare Git repository fetches only commits pointed to by branches and tags. Date selection uses a unified style.
- When creating an application, paths in the example directory and image build hints are shown as text.
- The community edition gateway grants access per resource by default. Build tools are updated to Go v238, Python v358, and Node.js v375.
- Sandbox preview opens the sandbox address directly, and creation returns after the sandbox is ready. Redis memory usage is calculated against the container memory limit.

### Fixed
- Editing an add-on plan in platform management keeps the configuration already filled in. A deployment can still be submitted when build arguments are left empty.
- After the permission center switches to V4, authorization, members, and permission model sync continue to work. The admin console pages open normally.
- When initializing an external-link application, an application ID that already exists is skipped and initialization continues.
- The RabbitMQ add-on can finish upgrading. The BKRepo add-on can be allocated within its quota.
- The resource quota shown in process configuration matches the selected plan.

### Changes
- The database type environment variable injected into applications changes from `BK_DATABASE_TYPE` to `BKPAAS_DB_TYPE`.
- For environments that already use Agent sandbox file storage and have not set an artifact bucket, the default bucket name changes. To keep the previous bucket, set it to `agent-sandbox-artifacts`. New deployments are unaffected.
- New deployments use the heroku-24 base image by default. Environments that already set a default image stay unchanged.
